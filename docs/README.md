# Документация Calista Tracker

Проектные, аналитические и защитные материалы к индивидуальной производственной практике.

## Карта документации

| Каталог | Что внутри | Когда открывать |
|---|---|---|
| [`competitors/`](competitors/) | Анализ 5+ конкурентов (Loop, Habitica, Streaks, HabitNow, Productive), таблица функций, 15+ сгруппированных болей из отзывов, обоснование «Гибкой серии», value proposition | Вопросы «почему такая функция», защита этапа 1 |
| [`uml/`](uml/) | Три Mermaid-диаграммы: Use Case, Class Diagram, Component/Layers Diagram + инструкция рендеринга | Вопросы по архитектуре, этап 2 |
| [`adr/`](adr/) | 6 Architecture Decision Records: паттерн, Flutter, Drift, уникальная функция, Riverpod, уведомления/iOS | Вопросы «почему именно это», компромиссы |
| [`wireframes/`](wireframes/) | ASCII-макеты экранов: «Сегодня», детали, форма, статистика, пустые состояния | Обсуждение UX/UI |
| [`demo/`](demo/) | Пошаговый сценарий демонстрации уникальной функции на 1 минуту + резервный план | Подготовка к защите, этап 8 |
| [`testing/`](testing/) | Чек-лист реального Android-устройства: разрешения, заморозки, reboot, timezone, производительность | Перед защитой, приёмка |
| [`presentation/`](presentation/) | Структура презентации на 5–7 минут и шпаргалка из 30 вопросов руководителя с ответами | Репетиция защиты |

## Принципы документации

1. **Актуальность коду.** Если меняется поведение, обновляется соответствующий ADR или чек-лист.
2. **Воспроизводимость.** Любая команда в документации должна выполняться из корня репозитория.
3. **Проверяемость.** Утверждения о тестах и сборках подтверждаются CI и локальным запуском.
4. **Защита.** Материалы `presentation/` и `demo/` рассчитаны на устный доклад без чтения слайдов.
