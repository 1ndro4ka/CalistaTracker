# ADR 0002: Выбор базовой технологии разработки (Flutter + Dart)

## Статус
Принято (Accepted)

## Контекст
ТЗ требует разработку мобильного приложения с приоритетом платформы Android (основная оценка), однако проект также нацелен на возможность сборки под iOS (дополнительный бонус и расширение аудитории). Требуется обеспечить высокую производительность пользовательского интерфейса (60/120 FPS), точный рендеринг кастомной дизайн-системы (тонкие hairline-линии, минималистичные монохромные графики, календари-heatmap) и детерминированную работу на обеих ОС.

## Принятое решение
Выбрать **Flutter (актуальная стабильная версия 3.x) и Dart (с полной статической типизацией и sound null-safety)**.

## Рассмотренные альтернативы
1. **Нативный Android (Kotlin + Jetpack Compose):**
   - *Плюсы:* эталонная интеграция с платформенными API Android.
   - *Минусы:* делает невозможной сборку под iOS без полного переписывания на Swift/SwiftUI; удваивает трудозатраты.
2. **React Native (TypeScript):**
   - *Плюсы:* популярный кроссплатформенный стек.
   - *Минусы:* зависимость от нативных мостов/Fabric; неоднородное поведение микроанимаций и кастомных Canvas-отрисовок на разных версиях ОС; сложности с гарантией 60 FPS для тонких векторных линий.

## Последствия
- **Положительные:** единая кодовая база для Android и iOS; декларативный UI с мощным механизмом `CustomPainter` и встроенными анимациями; единый язык Dart для логики и интерфейса; возможность компиляции под iOS в облаке (GitHub Actions) без физического наличия компьютера Mac у разработчика.
- **Отрицательные:** несколько больший начальный размер итогового APK по сравнению с нативным Kotlin-приложением за счет включения движка Flutter.
