# ADR 0003: Способ локального хранения данных (Drift / SQLite)

## Статус
Принято (Accepted)

## Контекст
ТЗ строго требует локальное хранение данных в базе данных. Трекер привычек оперирует реляционными связями: у привычки есть множественные отметки выполнения по датам, статусы заморозок, настройки времени напоминаний. Требуется надежность транзакций (ACID), типизированные SQL-запросы, поддержка миграций схемы и возможность запуска in-memory базы данных для быстрых интеграционных тестов.

## Принятое решение
Использовать пакет **Drift** (ранее Moor) с библиотекой **`sqlite3_flutter_libs`** поверх стандартного SQLite.

## Рассмотренные альтернативы
1. **SharedPreferences / Hive / Isar (NoSQL / Key-Value):**
   - *Плюсы:* быстрое прототипирование, отсутствие строгой схемы.
   - *Минусы:* SharedPreferences не является БД и не подходит для массивов истории; Hive не гарантирует ACID-транзакции при сложных выборках за диапазоны дат; Isar нестабилен при миграциях и имеет нерегулярные релизы.
2. **sqflite (чистый SQLite без ORM):**
   - *Плюсы:* низкоуровневый доступ к SQLite.
   - *Минусы:* запросы в виде «сырых» строк `rawQuery('SELECT...')`, отсутствие статической проверки типов на этапе компиляции, высокий риск опечаток в названиях столбцов.

## Последствия
- **Положительные:** 100% типобезопасность SQL-запросов и результатов выборки на этапе компиляции Dart; поддержка реактивных стримов (`watch()`); простота написания тестов через `NativeDatabase.memory()`; гарантированная сохранность данных пользователя даже при внезапном закрытии процесса ОС.
- **Отрицательные:** необходимость кодогенерации через `build_runner` при изменении схемы таблиц.
