# Структура презентации и тезисы защиты (5–7 минут)

> Формат: 10–12 слайдов, 5–7 минут доклада + 3–5 минут вопросов.
> Главная мысль: **не «ещё один трекер», а трекер, который не наказывает за один пропуск**.

## Слайд 1. Титульный (0:00–0:15)
**На экране:** Calista Tracker, Monochromatic Minimalist, Flutter + Clean Architecture, ФИО, группа, руководитель.

**Тезис:** «Calista Tracker — локальный трекер привычек с уникальной механикой “Гибкая серия”: заморозки пропусков и индекс стабильности».

## Слайд 2. Проблема (0:15–0:50)
**На экране:** 3 цитаты из отзывов конкурентов + цифра 15+ сгруппированных болей.

**Тезисы:**
- Главная причина удаления трекеров — не лень, а потеря прогресса из-за одного случайного пропуска.
- Классический streak («день 47 → день 0») вызывает «синдром разбитого окна» и демотивацию.
- Пользователю нужен честный прогресс, а не бинарный «всё или ничего».

## Слайд 3. Анализ конкурентов и ниша (0:50–1:20)
**На экране:** таблица Loop / Habitica / Streaks / HabitNow / Productive: серии, заморозки, статистика, цена, офлайн.

**Тезис:** у конкурентов либо нет защиты серии, либо она платная/ручная/игровая. Свободная ниша — **автоматическая бесплатная заморозка + прозрачная метрика стабильности** в минималистичном офлайн-приложении.

## Слайд 4. Уникальная функция (1:20–2:00)
**На экране:** формула и схема «выполнено / заморожено / пропущено».

**Тезисы:**
- У каждой привычки 2 бесплатные заморозки в календарный месяц.
- Пропуск автоматически закрывается заморозкой: серия не рвётся, но день **не** считается выполнением.
- Индекс стабильности = `выполненные дни / запланированные дни × 100%` за 30 дней.
- Третий пропуск в месяце при исчерпанной квоте действительно рвёт серию — дисциплина сохраняется.

## Слайд 5. Демонстрация (2:00–2:50)
**На экране:** живое приложение или 4 скриншота: карточка с `❄`, календарь, нажатие на замороженный день, статистика.

**Тезис:** «Показываю полный цикл: пропуск → автозаморозка → серия сохранена → пользователь может превратить заморозку в выполнение».

> Если живой показ невозможен — использовать `docs/demo/one-minute-demo.md`.

## Слайд 6. Архитектура (2:50–3:30)
**На экране:** Component/Layer Diagram из `docs/uml/component_diagram.md`.

**Тезисы:**
- Clean Architecture + Feature-first: `habits`, `stats`, `reminders`.
- `domain` — чистый Dart: сущности, use cases, интерфейсы репозиториев. Не зависит от Flutter/Drift.
- `data` — Drift/SQLite, мапперы, реализации репозиториев.
- `presentation` — Riverpod + GoRouter + дизайн-система.
- Внедрение зависимостей — через Riverpod-провайдеры, время — через `Clock`.

## Слайд 7. Данные и надёжность (3:30–4:00)
**На экране:** схема двух таблиц + индекс.

**Тезисы:**
- Drift (SQLite), таблицы `habits_table` и `completions_table`.
- Заморозка — такая же запись completion с `is_frozen = 1`, поэтому история восстанавливаема.
- Составной индекс `(habit_id, date)` ускоряет календарь и расчёт серий.
- Миграции версионированы (`schemaVersion = 2`), репозитории покрыты интеграционными тестами на in-memory SQLite.

## Слайд 8. Напоминания и платформа (4:00–4:30)
**На экране:** цепочка «форма → permissions → zonedSchedule → AlarmManager → tap → GoRouter».

**Тезисы:**
- `flutter_local_notifications` + `timezone`.
- Android 13+: `POST_NOTIFICATIONS`; Android 12+: `SCHEDULE_EXACT_ALARM` с fallback на inexact.
- Переживание перезагрузки: `ScheduledNotificationBootReceiver` + повторная синхронизация на старте.
- Нажатие по уведомлению открывает детальную карточку через payload `habitId`.
- iOS: авторизация через `UNUserNotificationCenter`, сборка IPA в GitHub Actions без Mac.

## Слайд 9. Качество и тестирование (4:30–5:00)
**На экране:** 48 тестов, список групп (включая 2 теста секретной панели и 2 теста экрана статистики).

**Демо-ход:** долгое нажатие на заголовок → `/dev` → «Создать демо-привычки» → «−1 день» → увидеть `❄` в календаре → «+1 день» / «Выбрать дату» → показать, что квота обновляется.

**Тезисы:**
- 12 тестов серий: пропуски, месячная квота, выходные, граница года, задним числом.
- 10 тестов автозаморозки и FreezePolicy.
- 5 тестов стабильности, 6 тестов CRUD/toggle, 5 интеграционных тестов Drift.
- 4 теста парсинга времени напоминаний, 2 widget-теста.
- `flutter analyze` без замечаний.
- CI: analyze + test на каждый push, отдельные workflow сборки APK и IPA.

## Слайд 10. Ограничения и развитие (5:00–5:30)
**На экране:** «Что дальше».

**Тезисы:**
- Сейчас: 100% офлайн, без аккаунтов и облака — приватность по умолчанию.
- Ограничения: нет синхронизации между устройствами; iOS-сборка без подписи (Sideloadly, 7 дней); desktop — не целевая платформа для напоминаний.
- Развитие: экспорт CSV, виджеты home screen, Apple Health/Google Fit, шифрование бэкапа.

## Слайд 11. Итог (5:30–6:00)
**Тезис:** «Calista Tracker доказывает: удержание привычки можно измерять честно, не наказывая пользователя за один плохой день. Спасибо, готов ответить на вопросы».
